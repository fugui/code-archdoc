# code-archdoc: 阶段一特性清单与需求边界 (SDD) 提示词指令

## 角色定位与工程原则
你是一名资深 Go 全栈系统架构师与产品领域专家。我们将采用 **SDD (规范驱动开发) + TDD (测试驱动开发)** 的工程方法，在 CodeBench 微前端体系下开发 **code-archdoc（代码设计文档反推）** 业务子系统。

开发过程**严禁直接跳过设计堆砌业务代码**，必须严格遵循：
**「阶段一：特性与边界明确 (`01-features`) -> 阶段二：架构与模型定稿 (`02-design`) -> 阶段三：契约冻结与 TDD 任务拆解 (`03-api` & `04-tasks`) -> 阶段四：TDD 测试先行与分阶段实施」**。

---

## 1. 模块基础元数据契约
- **模块唯一标识 (`ModuleKey`)**：`archdoc`（网关与前端路由前缀 `/archdoc`）
- **模块中文名称**：`代码设计文档反推`（服务名 `Code-Archdoc`）
- **端口分配**：Go 后端监听 `:8092`，前端 Vite 独立调试端口 `5182`
- **数据库隔离策略**：与 CodeBench 共享 PostgreSQL 实例（复用 `users`, `departments`, `audit_logs`），本模块所有业务表强制使用前缀 `archdoc_`
- **RBAC 权限角色**：模块管理员角色为 `archdoc_admin`（`super_admin` 拥有同等最高权限）

## 2. 阶段一执行指令（生成或细化 `docs/01-features/01-feature-matrix.md`）
请结合具体业务诉求，在 `docs/01-features/01-feature-matrix.md` 中输出详尽、结构化、可直接指导后续架构设计与 TDD 验收的**特性清单矩阵与范围界定规范**：

1. **系统愿景与核心价值主张**：明确 `代码设计文档反推` 解决的核心业务痛点与目标用户角色。
2. **结构化功能特性矩阵表格**：
   - 按核心业务子域划分（列包含：特性编号 `F-XX`、特性名称、优先级 `P0/P1/P2`、功能描述与技术规范、TDD 验收衡量标准）。
3. **核心业务验收场景矩阵 (Verification Scenarios)**：设计 `SC-01` ~ `SC-05` 端到端核心业务场景（含正常主链路、参数校验拦截、RBAC 越权拦截、并发/边界场景）。
4. **明确定义 Non-Goals（非目标边界）**：界定当前版本明确不做的功能，防止需求蔓延。
5. **非功能性与安全红线 (NFR & Guardrails)**：明确响应延迟、数据隔离、字段级审计与亮/暗双模主题适配要求。
6. **在本阶段定稿确认前，请勿修改或新增任何 `.go` / `.tsx` 业务代码。**

## 3. 已确认的首期业务前提（Stage 1 需求澄清结论）
1. **主力语言栈（P0）**：优先覆盖 **C/C++（含 Protobuf / CROS RPC 服务）** 与 **Java / Python** 后端服务；Go 与 TypeScript/React 暂列 P1/P2。
2. **分析对象粒度（P0）**：支持单代码仓（`Repository`）及 Monorepo 子目录（关联 `code-bench` 的 `ArchitectureElement.RepoID + Subdirectory`）；跨多仓子系统聚合放至 P1。
3. **模板与多视角文档套件**：P0 内置 4 篇默认视角（系统架构与核心链路、数据模型与接口契约、配置与运维部署、代码导读），同时支持管理员导入/编辑自有设计文档模板覆盖或扩展。
4. **过时旧文档策略**：以代码为唯一事实源反推，将既有文档作为对照输入产出「Gap 差异报告」，谨慎摘录旧文档业务背景供人工确认。
5. **Chat 协同边界（P0）**：落地双栏协同工作台（Canvas），支持选中章节局部指令、源码只读 Tool Calling、Diff 审阅应用、行级证据跳转与章节锁定；多条批注一键批量修订与 AI 主动反向澄清放至 P1。
6. **Git 拉取与发布出口**：P0 假定宿主机已配置全局免密只读 SSH Key（不自建凭据库），定稿后同步展示至 `code-bench` 文档中心并支持 Markdown/ZIP 导出；凭据保险库与回推源码仓提 MR/PR 放至 P1。
7. **LLM 算力接入**：P0 支持直连任意 OpenAI Compatible HTTP/SSE 接口（配置 `BaseURL` + `APIKey` + 分层模型），不强依赖特定网关或外部 CLI 执行器。
8. **RBAC 权限**：已发布文档全员只读可见；仓库负责人（`Owner` / `RelatedMembers`）与 `archdoc_admin` / `super_admin` 可触发生成、Chat 精修与发布；管理员独占模板套件与 LLM 配置权限。
